# Solve-It Grid

## Creation and editing

Task sets use the shared creation-date library, fading, and archive settings from Todo List. The new-set introduction replaces its redundant header label with a subtle badge reading “Designed for those with ADHD. Verified via. Licensed Therapy” followed by the verified icon. The verification claim requires real review and authorization before public use. Creating a new task set begins with a calm introduction and a dedicated name step. **Let’s begin** opens the name step and focuses the name field. **Continue** moves through each category individually, with only the current category’s heading, description, and items visible. The four-tab category navigation and advisory balance panel are hidden during creation; examples expand on request, and each item's settings expand from its gear button. Back on the first category returns to the name step, and Back from naming returns to the introduction, preserving the draft. During new-set creation, a small question-mark button beside each category title opens an animated explanation popover, with a More information action opening an animated shared dialog of short identification questions. Both transitions respect reduced motion. Existing task sets open the fuller editor directly, keeping the category tabs, examples, repeat controls, and balance display. New task sets are only saved after the fourth builder step; cancelling discards the draft after confirmation when it has changed. Existing empty task sets open the same setup. Editing retains the creation date and completion marks for unchanged tasks; changing a task's text makes it available again. Saving edits resets the displayed round.

The guided lists, in order, are Fires, Passive Fun, Shoulds & Oughts, and Stimulating Fun (the stored category ID remains unchanged for backward compatibility). Each can be empty and has no item-count cap. New drafts default to an editable name using the local month and ordinal day, such as “Task set for October 27th”. Each item appears in a compact horizontal row: number, custom-styled multiline text entry (without the browser's resize handle), a square repeating toggle, and a settings gear. The repeating square shows a playlist-style Repeat 1 icon for a one-time item and repeat arrows when enabled, with cleaned-up matching arrow paths and a clearly centered “1” glyph, sized consistently with the outlined gear button. The gear only appears while Repeat is enabled, and opens the repeat-count controls beneath the row in either creation or edit mode. Disabling Repeat also closes the settings. Removal is independently available from a trash icon for every item; the repeat tooltip explains that repeating means returning to the item later. Repeating is off by default; turning it on defaults to Forever (`-1`). Positive values in the dropdown indicate how many **additional** times the item can be completed after its first completion (e.g., 2 extra times = 3 total completions). Finite repeats become unavailable after their limit; unlimited repeats remain eligible in future rounds. On the first list of new-set creation, a single unobtrusive hint encourages small, manageable periods of work (approximately an hour or two at most) and Repeat for longer activities. The Repeat settings also explain revisiting an item after checking in with yourself, rather than breaking work into subtasks. Examples favor bounded periods of time, and the welcome screen emphasizes working on one item, checking in, and deciding what deserves attention next. Changing item text or repeating options resets that item's completion progress, while unchanged items retain progress. Each item has a stable ID for future metadata such as priorities; priorities are not implemented yet. Text is limited to 10,000 characters per item.

The advisory balance score uses item counts: `100 × (1 − sum(abs(count − total/4)) / (1.5 × total))`, bounded to 0–100. Equal counts score 100; one occupied list scores 0. Empty plans have no score. The score does not estimate effort/time and never blocks saving.

## Grid and rounds

| Number | List | Position |
| --- | --- | --- |
| 1 | Fires | Top left |
| 2 | Passive Fun | Bottom right |
| 3 | Shoulds & Oughts | Bottom left |
| 4 | Stimulated Fun | Top right |

Stimulation increases upward; fun increases to the right. Each new draw independently selects one random available task from every nonempty remaining list; available includes repeating tasks that have not reached their limit. Empty quadrants do not block the route. Completing a quadrant records that round's check, and for repeating items increments its completion count. Each completed draw retains its own check state even when an item appears again in later draws. Undo or rewind reverses those counts; restart clears all completion counts.

The chart is an open, neutral surface divided by two axes, without quadrant cards, fills, or borders. Circled numbers sit around the intersection: 1 above-left, 4 above-right, 3 below-left, and 2 below-right. Each axis caption has a directional arrow icon to the left of its text; these arrows describe the axes, not the task route. Category titles are slightly larger on desktop and horizontally centered with their icons on narrow/mobile layouts; the main task text has slightly subdued contrast. Available tasks use a forward arrow inside the quadrant cue, never a completion checkmark. The arrow and cue do not translate or scale on hover; only their colors respond. Completed quadrants retain a static checkmark with struck-through text; the full-screen work view provides the sole completion celebration. The play view shows no progress bar or completed/total count. Once history exists, a Previous button allows reviewing earlier points without progress totals or round numbers. Next appears only when browsing earlier points. Return to this point opens the standard confirmation dialog before rewinding. Restoring an earlier point never auto-advances to a fresh draw: when the restored point contains only skipped items, the latest skipped item is reopened so the selected grid is usable. Keyboard focus is shown around the number rather than outlining the quadrant. The board flexes to the pane's available height; long task text scrolls within its quadrant.

Selecting an available quadrant opens a dedicated work view before any completion is recorded. Marking an item finished uses an accessible, prominent button (instead of a native checkbox) that saves immediately and transitions directly to a full-screen, unboxed success celebration: an overshooting checkmark, expanding ring, sparkles, and a short positive label before returning to the grid in about 1.1 seconds. After every work-screen completion, the existing square-mosaic transition plays once before revealing the grid again. When quadrants remain, their selections and saved progress stay in the same draw; after the final quadrant, the next draw is selected as usual. If no tasks remain, the mosaic transitions to the completion summary. The grid retains a **static** completed check indicator without replaying its checkmark animation, and the redundant grid pulse and confetti stay disabled. Reduced motion presents the completed check immediately with a shorter return delay. The work screen uses a smaller, unboxed focus reminder. The finish action stands alone above a quieter, vertically separated Choose something else button, instead of competing side-by-side actions. The celebration is only shown for an actual completion, not when opening an item or switching activities. The work view offers Time, Until finished, or Both. Time and Both allow a 15/25/45/60/90/120-minute gentle check-in; Until finished offers an obvious completion control and a default one-hour reminder, with no deadline to finish. Both offers that same control and a timed reminder. A small speaker icon appears after the selectable check-in times in Time/Both setup; it previews the real in-app check-in prompt and also attempts a sample browser/system notification with the same generic reminder wording, explicitly labeled Preview. The click requests browser notification permission if it has not already been decided. If the browser blocks or cannot deliver the sample notification, the in-app preview explains the limitation and remains usable. Preview notifications have a separate browser tag from real reminders and never schedule a timer, stamp a notification deadline, or alter task progress. All actions in preview return to the setup choices, and Back to choices exits the preview. It is not shown on the active-work screen. At the reminder the user sees a non-blocking check-in: Keep going (reschedule), Choose something else (leave the item unfinished), or I'm finished (record completion). The same choose-something-else action is available before any reminder, skips the selected item in the current draw, and keeps it eligible to return in future draws. It moves to the next available quadrant, or advances to a new draw when none remain. The work screen has Back to grid at all times. An active reminder timestamp is persisted alongside the task set in IndexedDB, so returning to the app after its deadline shows the pending check-in. When a new task set is created, users whose browsers support notifications see a short optional permission explanation: notifications are only for Solve-It Grid reminders and the browser tab needs to stay open. Clicking Allow notifications requests the browser's actual permission; Not now leaves the grid fully usable. Previously granted permission is reused, and denied/unsupported browsers continue with the in-app check-in. With permission granted, the app shell checks due reminders while the Dynamic Learner tab is open (even when a different app is selected) and hands each reminder to the browser's system notification API once. Its delivered deadline is recorded on the active check-in to avoid duplicates across reloads, and Keep going clears that marker when it schedules the next reminder. Notifications contain no task text, do not complete or advance the grid, and clicking one brings the browser window forward. Delivery timing depends on browser background throttling, operating-system and browser notification settings, and API support; reminders cannot fire after the tab/browser closes because this offline site has no push service. The in-app prompt remains the fallback. Selecting a different item does not automatically mark the previous one completed. Completing a task immediately unlocks the next available quadrant; later quadrants remain locked. New task sets and rounds have no timed safety pause: the first available quadrant can be checked immediately, even during the new-round reveal animation. The lock hint for skipping ahead keeps its intentional one-second fade-out. Task text, titles, numbers, and hints remain neutral. Available tasks show a small forward-arrow cue with a neutral hover/focus color response, without sliding or bouncing. A single activation on a later locked quadrant only gives blocked feedback; double-click, double-tap, or two quick keyboard activations deliberately skip ahead. Holding a key cannot repeatedly activate quadrants. The latest completed quadrant in the current draw can be selected to undo it; older completions must be undone in reverse route order. Undo also restores any earlier skipped quadrants belonging to that action. A short completion hold allows immediate undo before the next draw. Up to 100 previous draws remain browsable with Previous/Next; viewing past rounds never changes progress. Tasks skipped in an earlier round continue to appear skipped there, even if completed during a later draw. Return to this point asks for confirmation, clears completions from the newer draws, and restores the selected point with its last completion undone. The last draw remains undoable after the final completion summary.

Later quadrants show a red lock and are locked against a single activation. Double-click, double-tap, or two quick keyboard activations confirm skipping ahead directly, without a modal. This skips earlier ready quadrants for the current draw and opens the selected item’s work screen; completion is only recorded when the user chooses to finish. Skipped tasks remain incomplete and can be drawn later. A single activation only gives lock feedback and changes no task state.

When no ready quadrants remain after choosing something else, the existing grid rotation proceeds normally. After any finished item, the full-screen success gives way to the same square-mosaic animation before showing the updated grid, without inserting an extra celebration. A new draw starts with its quadrants blank while the app workspace turns white and a smaller centered, true 1:1 square mosaic with transparent, black-outlined cells touching on a shared 40px pitch pops diagonally from the top-left toward the bottom-right, scales slightly past full size, and settles. In wider workspaces the mosaic uses at most 60% of the horizontal space or 90% of the height, whichever is smaller; in taller/mobile workspaces it uses at most 60% of the height or 90% of the width, whichever is smaller. The diagonal appearance takes around 550ms; the fully drawn mosaic holds for about 1.85 seconds, disappears immediately, and then the individual quadrants stagger into view. The mosaic is rendered as a transient canvas overlay covering the work area and never saved; the canvas animation stops if navigation or deactivation interrupts it. During the mosaic only, quadrants are unavailable; when the items appear they are immediately actionable, even if their reveal animation is still finishing. Exhausted task sets finish with a summary and offer editing or an explicitly confirmed restart. Reduced motion skips rotation, mosaic drawing, and staggered movement while retaining completion feedback. Timers stop when the view is deactivated or unmounted. Saved task completion, current round, and recent round history survive app switching, reload, and backups; visual phases do not persist.

## v1 motion principles

The v1 polish pass applies brief, low-distraction motion where state or context changes: category navigation and field selection ease between visual states; adding/removing list items uses a small fade-and-settle (with surrounding items repositioning smoothly); Repeat options expand/collapse; the active work view, check-in prompt, and timing choices crossfade; navigation/history and workspace headings fade in when shown. Existing introductory help, grid construction, round reveals, and the single full-screen completion celebration retain their established timing. No motion is required to understand or operate a control; input text and focus positions do not animate. Reduced-motion settings remove these transitions without changing actions, focusability, or stored progress. Hover indicators on grid arrows remain stationary.

## Category meanings

- **Fires:** Urgent responsibilities that must be handled soon or delaying them could have serious consequences.
- **Passive Fun:** Enjoyable and relaxing, with limited mental effort and little distress if interrupted.
- **Shoulds & Oughts:** Responsibilities the person knows need doing but has actively postponed.
- **Stimulating Fun:** Enjoyable and mentally engaging activities that can be uncomfortable to interrupt, such as dates, concerts, vacations or absorbing hobbies.

The builder's summaries, longer explanations, identification prompts, and the quadrant headings follow these definitions.

## Ownership

- `library-model.ts`: dated task-set model and feature validation.
- `task-model.ts`: categories, tasks, balance, random draws, round state, validation.
- `task-set-builder.ts` / `.css`: unsaved guided creation and editing.
- `task-grid.ts` / `.css`: actionable quadrants, confirmations, feedback, round transitions, and navigation into work mode.
- `task-check-in.ts` / `.css`: optional work-mode choices, clock- and completion-based reminders, and gentle reflection controls.
- `grid-construction.ts`: short-lived canvas mosaic for the new-round reveal.
- `solve-it-grid.ts`: dated library and feature composition.

IndexedDB schema v3 stores task-set configuration/rounds in `solveItTaskSets`, individual tasks in `solveItTasks`, and list ordering in `collections`. Workspace v1 backup compatibility remains in the app mapping and feature validators.
