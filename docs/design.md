# Visual system

Dynamic Learner takes its visual basis from Microsoft Fluent 2, using native CSS rather than adding a component library. References: [typography](https://fluent2.microsoft.design/typography), [layout](https://fluent2.microsoft.design/layout), [design tokens](https://fluent2.microsoft.design/design-tokens), and [motion](https://fluent2.microsoft.design/motion). This is a Fluent-inspired implementation, not a claim of certified conformance.

- Use the shared Segoe UI/native font stack, 14/20 body text, 12/16 supporting text, and restrained semibold headings. Use sentence case.
- Use the four-pixel spacing rhythm. Neutral surfaces and dividers organize the workspace; blue identifies primary actions and selection. Reserve red for destructive actions and the paper's ruling.
- Put palette-independent shared values in `src/styles/tokens.css` and selectable theme palettes in `src/styles/themes.css`. Register selectable themes in `src/app/theme.ts`. Feature chrome consumes semantic variables rather than checking theme IDs. Shared control dimensions, typography, focus, and interaction states belong in `base.css`; navigation belongs in `shell.css`.
- Reuse shared button classes. Card navigation uses three equal grid columns, so Previous, Show front/back, and Next/Finish have matching dimensions even as labels change. Touch controls have a 44-pixel minimum height.
- Left-align dialog descriptions, forms, and multiline action choices. Shared compact buttons center their short labels; when reusing them for a title plus description, override the layout alignment as well as `text-align`. Keep all text in a choice on the same starting edge, with supporting text in the shared 12/16 style. Centered creation/empty states are intentional exceptions, not the default for feature content.
- Extend an existing app pattern before inventing a new one. Keep workspace headings at the shared type scale, use sentence case instead of promotional eyebrow text, and avoid turning routine tools into landing pages. Feature paper/quiz content can have its own reading treatment; surrounding controls and dialogs retain the Fluent workspace language.
- Keep the library and card list flush with the workspace. Avoid additional floating cards, shadows, borders, or independent color palettes around ordinary controls. The index card keeps its red margin, blue writing lines, and subtle stacked-paper elevation.
- Delete individual cards immediately. Never request deletion confirmation for an empty container: sets with no cards and groups with no children are empty. Confirm deletion only for populated sets and groups.
- Use short, consistent transitions for drawers, selection feedback, and card changes. Respect reduced motion. Preserve visible keyboard focus, native dialog behavior, and readable text.

Feature styles live beside their components. `index-cards.css` owns the library and selected-item frame; `card-set.css` owns the paper, review controls, and workspace composition; `card-list.css` owns the adjacent list and narrow horizontal strip. Review setup keeps its feature stylesheet; fullscreen deletion uses the shared `styles/delete-confirmation.css`.

Light and Dark are the initial registered application themes. Each registered theme declares whether it is a light or dark appearance. The header Theme button opens a compact modal with manual selection plus system-following mode, which is enabled by default for new preferences; system mode assigns one registered light theme and one registered dark theme, resolves between them with `prefers-color-scheme`, and reacts to system changes. Theme preferences remain best-effort local UI state, separate from workspace data and backups. Adding another fixed theme means adding its registry metadata and one `data-theme` palette in `themes.css`; it automatically becomes available for its matching light/dark role. A future theme editor should override the same semantic custom properties from a user-selected primary color rather than introducing feature-specific color rules. Physical study surfaces keep their saved choices such as White or Cream, while those choices resolve through paired light/dark paper tokens for the sheet, compatible ink, ruling, and Graph Paper chrome.

Word Search uses a snug outer grid frame without internal gridlines. `puzzle-game.css` owns the grid and continuous rounded SVG word highlights; `display-settings.css` owns its appearance dialog. Fit mode balances viewport width/height with readable letters: dense puzzle cells have a 30-pixel minimum, increasing for larger text, while ordinary touch controls retain the shared 44-pixel minimum. Larger grids scroll rather than shrink further. Found words, answer reveals, and hints use continuous capsule/circle outlines; the active outline follows the mouse. Highlighted letters take the selected highlight color over translucent fills. Small upright LTR labels sit beneath completed/revealed word outlines. Defaults are 95% letter size, regular weight, and instant movement. Every cell has explicit equal width and height; the word bank sits beside the grid rather than at the far edge of the workspace. Motion settings and system reduced-motion preferences disable transitions and fade effects.

## Index-card geometry

Untitled cards keep their title area blank during review in both Flash Cards and Fill in the Blanks. The Untitled card placeholder appears only while editing; the card list retains its Card 1, Card 2 numbering fallback. Manually review titled/untitled cards, flip where applicable, and end review to confirm the editable placeholder returns without changing card data or list labels.

The paper uses a fixed landscape 5:3 aspect ratio, matching the traditional 3 × 5-inch format. Quarter-inch ruling is modeled as 5% of the card width. Our layout reserves half an inch for the editable title and ten quarter-inch writing rows extending to the bottom edge. The row count is this app's layout choice; ruling and margins vary between physical products. Reference: [Pacon 3 × 5-inch, quarter-inch ruled cards](https://www.teachersparadise.com/c/pacon-index-cards-white-ruled-1-4-ruled-3-x-5-100-cards/).

`card-set.css` makes the stack an inline-size container. Paper typography, ruling, and margins use its container width, so the same text and number of rows scale together across window and sidebar sizes. These are physical proportions, not a promise of actual inches on an uncalibrated screen. Both sides retain ruling for editing. Existing longer content scrolls within the ten-row writing area; the paper never stretches and no new content limit is imposed.

The library's Settings footer opens Display options with a live sample card. `display-options.ts` is the canonical source for choices, defaults, bounds, validation, and CSS mapping. The feature entry applies these CSS properties to all sets and the preview. Defaults use regular-weight Serif (Georgia), neutral pencil ink (#3d3d3d), 100% text/card sizing, and a one-pixel downward text adjustment. Sans, larger/smaller text and cards, darker ink, and vertical alignment are configurable. No font download is required. Text size is relative to the paper; card size is a preferred responsive scale, bounded by the available screen space.

Adjust text independently of the paper: line spacing, rule positions, horizontal margins, and aspect ratio do not change with font settings. The red margin is drawn on the card face to reach the bottom regardless of textarea scrolling. The rest of the interface retains its shared UI typography. Display settings save across sets and reloads and travel in workspace backups; Reset display defaults changes only these preferences.

## Manual review

### Home

Your learning apps has a full-width, softly rounded search bar directly above the app cards, with the shared search icon and a Clear search button. Search matches app names and descriptions without case sensitivity; each entered word must match. The bar stays outside the scrolling app grid, aligns to the cards at every width, and is at least 40px tall (44px on touch). Focus transitions emphasize its border and icon. Vue TransitionGroup gives filtered cards short fade/slide and repositioning transitions; outgoing cards keep their geometry and become inert until removed. Reduced motion disables these transitions. A no-results message occupies the grid when nothing matches. Escape clears the field while it is focused. Manually check partial names, description words, multiword searches, whitespace, no results, clearing, keyboard navigation, both themes, rapid typing/clearing, reduced motion, and narrow/short windows.

The app cards are subtly grouped under small semibold, secondary-text headings with neutral divider lines: Utilities (Calculator, Notebook, Todo List), Applications (Index Cards, Word Search, Crossword), and Mastery (Study Guide, Review). Group membership and display order live in `feature-definitions.ts`; search hides empty groups, and headings share the card filtering transitions. App titles sit one heading level below their category. Manually check group order, search results across groups, disappearance/reappearance of empty headings, keyboard reading order, both themes, and reduced motion.

Home stays within the available viewport, with its heading and footer outside the scrolling app grid. Spacious cards retain their stacked artwork, title, description, and Open link, using three columns on wider content areas, two on intermediate widths, and one on phones. Artwork remains 56px, with 24px desktop card padding and a 220px minimum height. Reduced spacing around the grid leaves more room for the cards. The grid scrolls only when the cards exceed its available space; adding future apps does not make the whole page scroll. Padding inside the grid keeps keyboard focus outlines visible.

Manually check that all groups and apps are reachable, with only the card grid scrolling when its contents exceed the available height. Resize to narrow and short windows and use browser zoom; confirm only the app grid scrolls when needed, every card remains reachable by keyboard and touch, and the heading and footer stay visible. Review a longer app list during future feature additions and check both themes.

### Calculator

The result screen keeps the existing flat surface, border, and UI font. A very faint background of rectangular 5 × 7 pixel matrices marks character positions behind the ordinary result text, with a smaller version behind the expression row. The matrices stretch vertically by 18% without widening their character slots. This decoration takes its color from the current theme and scales with each row's text size; errors omit the result decoration, and forced-color modes omit both. Result text remains native, selectable, and available to assistive technology. The scientific power key uses the same neutral styling as the other scientific functions.

Calculator adapts to its available content width. Wide layouts place scientific and numeric keypads beside one another, reducing the number of stacked key rows; History sits beside the machine when both panels have enough room. Narrow layouts initially show the numeric keypad and provide a Scientific disclosure next to DEG/RAD. Expanding or hiding scientific controls keeps the expression, answer, memory, and history intact. The disclosure choice is temporary presentation state, retained while the Calculator remains mounted. On wider layouts the scientific keys are always visible. Display height and result text are restrained, error messages wrap, spacing is compact, and short mouse-driven windows use smaller keys. Touch controls retain at least 44px height. History has a bounded scrolling list, and very small windows can scroll the page without clipping controls. All existing operations and keyboard shortcuts remain available.

### Lined Paper

Notebook Lined Paper follows the Index Cards paper treatment with blue rules, a red margin, subtle elevation, and regular Georgia text in pencil-colored ink. Paper defaults to white, with cream available in Settings. Its portrait sheet uses US Letter's 8.5 × 11 proportions and college ruling of 9/32 inch, as shown in the [School Smart ruled-paper guide](https://www.schoolspecialty.com/wcsstore/SSIB2BStorefrontAssetStore/documents/spec-sheets/ruled-paper-guide.pdf). The layout uses a 1.25-inch left margin and title area. Each sheet has its own editable title, independent of the other sheets and the library filename. A separate textarea to the left of the margin is right-aligned, has no placeholder, and shares the main text’s line spacing and baseline. The writing areas paginate independently into numbered sheets, using native textarea measurements. Main text and margin text remain separate continuous streams. Dimensions scale with the sheet rather than promising physical inches on screen. Narrow views retain at least 16px text and 24px rows, with fewer visible rows. Long notes create additional sheets. Each sheet has three decorative punch holes with inset shadows and an optional reserved gutter. Title, main text, and margin text include a three-pixel upward base correction in addition to the saved vertical-offset setting (default 0px). This places the default text one pixel above the previous default alignment; ruling positions remain unchanged. Existing saved display choices remain in effect until edited or reset. Pagination uses every complete ruled row, including the last blue rule near the bottom edge of the paper. It keeps the maximum fitting text prefix on the current sheet instead of pulling an already-written word or line onto the next page. Display options allow independent font, text size, ink, paper color, ruling, Letter/A4 size, punch-hole visibility, and vertical offset for Lined Paper. The Markdown tab separately controls source and preview typography; the Graph Paper tab controls its own paper, ruling, and coordinate appearance.

Manually create a Lined Paper document, rename it, enter paragraphs and long wrapped lines, and type or paste enough text to overflow the initial sheet. Give the first three sheets different titles and rename the library entry separately; confirm all four remain independent. Reload and round-trip a backup, then shorten the body text or change display settings: titled sheets should remain visible with their headings attached to the same page numbers. A document containing only a later-page heading must still require deletion confirmation. Write margin-only notes and check right alignment without placeholder text. Check text/rule alignment in both writing areas, page boundaries, keyboard focus, selection, undo, and paste. Check that typing reaches the last complete blue rule near the bottom edge and crossing a page boundary does not pull existing text forward. Check typing and Backspace/Delete across page boundaries, emoji and IME input, margin-only overflow, and editing a blank margin on a later page. Resize or change display settings and confirm the complete text remains intact as pages reflow. Resize the library and window, including a phone with its keyboard open; confirm notes and location controls remain reachable. Reload, switch documents, and round-trip a workspace backup. Restore a legacy lined record with empty data and confirm it opens blank and editable. Invalid text data or unknown fields must reject replacement. Confirm blank-note deletion is immediate and populated-note deletion supports Cancel and Escape, including notes with only a title or margin text. Restore an older text-only record and confirm its former displayed title is preserved independently; round-trip blank titles and margin notes too.

### Graph Paper

Graph Paper uses portrait US Letter (8.5 × 11 inches) and quarter-inch squares by default, matching common [commercial 4-squares-per-inch graph paper](https://rspaperproducts.com/product/loose-leaf-filler-paper-4x4-graph-ruled-80-sheets/). A4, fifth-inch, and 5 mm ruling are optional. Screen dimensions scale proportionally with the sheet. The sheet has white margins, an independent editable heading, light blue square ruling, restrained axes, and six distinguishable plot inks. Expressions sit in an adjacent panel and stack above the sheet on narrow workspaces. Expression plots and visual drawings share one sheet and remain visible together. The right-side vertical tool rail starts with an arrow on desktop or outlined circle on mobile, selected by default, followed by an arrow-cross pan tool and magnifying-glass zoom tool. Point, connection, and erasing tools are always available; contextual controls stay on the right. The top bar keeps a zoom percentage button, Reset view, units, and drawing undo/redo; notes sit below the sheet. The paper scrolls horizontally before becoming too small; graph zoom magnifies grid squares, curves, and drawn points inside the fixed sheet, independently of units per square. Click zoom follows familiar percentages; scrubby zoom uses whole percentages. Subtle optional subdivisions and readable main labels adapt to magnification and screen width. Snap spacing is selectable independently of visible subdivisions. The initial page stays blank until expressions or visual points are added. Appearance controls and reset are independent of Lined Paper and Markdown. See [graph-paper.md](graph-paper.md) for the focused manual review.

The right-side gear also exposes measurements. Right-clicking a point or segment opens its contextual controls with position/ink edits and applicable lengths, slope, angle, midpoint, and closed-region area/perimeter readouts. A point supports long-press with Select active on touch screens. Sheet choices independently show names, coordinates, segment lengths, or area labels; area labels lightly tint their region. Per-point coordinate labels can inherit or override the sheet. Labels begin restrained, with names visible and measurements hidden. Pinch magnifies over the grid, and two fingers pan from any tool; adding a second finger cancels drawing so navigation cannot accidentally add or erase content. Single-finger blank Select touches scroll the surrounding sheet/page, while margins and the title retain normal page interaction.

### Study Guide map study

Map editing and Map study are separate surfaces. New or incomplete maps open in the editor; once a map is fully connected and study-ready, selecting or reopening it lands on the Map Study overview by default, with Back to editor available for deliberate changes. The editor shows snapped topic stops and only user-created two-way paths; it never derives route lines from array order. Paths form an acyclic branching tree: connecting two topics that are already reachable from one another would close a loop, so that attempt is rejected with a brief semantic-danger path flash. Connect guidance floats over the editor and fades without changing layout height. One stop is explicitly marked Start. Study is available only when every topic is reachable from that starting stop. The study overview follows Review Study's restrained left-aligned session language, then replaces editing chrome with a clean route map and topic panel. Bullet points appear one at a time; revealing the final nonblank bullet immediately marks the stop visited. Completed stops use the semantic success color, the active route uses brand color, and the traveler/camera move smoothly between stops. At a fork the learner chooses an unvisited neighbor. At a dead end the session backtracks through the current depth-first path to the nearest visited fork with unfinished work, so branches can visibly require returning before continuing. Empty topics count as visited on arrival. Reduced motion makes route changes immediate. Study progress is session-only.

Manually create a connected map with at least one fork and one dead end, choose a non-first starting stop, and give topics multiple titled bullet sections. Confirm a newly created/incomplete map stays in the editor, then leave and reselect a study-ready map and confirm it opens on the Study overview; Back to editor should return to authoring without losing content. Confirm only explicit connections render; branches are allowed; duplicate or cycle-closing connections flash red and are not created; Connect guidance does not shift the canvas; deleting a topic removes its paths; removing a path can disable Start studying when it disconnects the map. Start Study, reveal points one at a time, and confirm the stop turns visited only after its final point. Choose different branch orders, reach a dead end, backtrack across multiple visited stops, and finish every reachable topic exactly once. Check a rejected cycle attempt, a single-topic map, an empty-bullet topic, reduced motion, narrow/mobile layout, dark theme, End studying, Study again, reload, and backup round-trip. Study progress must reset while saved paths/start/topic content persist.
