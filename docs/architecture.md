# Architecture

## Runtime

Use Node.js 24 or newer and install the lockfile with `npm ci`. `npm start` launches webpack-dev-server at `127.0.0.1:3000` with live reload; `HOST` and `PORT` override the address. Development assets are served from memory, with source maps and no access to repository files. Known feature paths without a trailing slash redirect to their canonical form, preserving query strings; unknown routes and missing assets return 404. Source changes reload the page rather than attempting to hot-replace stateful feature components.

`npm run build` runs webpack in production mode, cleans ignored `dist/`, and emits hashed JavaScript/CSS bundles, artwork, licenses, route HTML, a 404 page, and `.nojekyll`. Development builds stay in memory and rebuild automatically through webpack-dev-server; production output is generated only by the explicit build command.

`src/app/app.ts` is the webpack entry and imports `src/styles/index.css`. Components import Vue APIs from the pinned npm dependency; no application or Vue globals and no runtime CDN are required. Source uses strict TypeScript ES modules and plain render-function components. Browser source is checked by `tsconfig.app.json`; webpack and build tooling are checked by `tsconfig.node.json`. The shared configuration keeps `strict: true` without an `allowJs` compatibility boundary. There is no single-file component compilation, Bootstrap, jQuery, or router/state library. `ts-loader` compiles and checks browser TypeScript during webpack builds and development rebuilds; `.ts` extension aliases resolve rewritten TypeScript imports. Node 24 runs `.mts` tooling with native type stripping; the CLI uses `--disable-interpret` rather than a separate loader. `npm run typecheck` checks browser and Node configurations, and production builds require it to pass. Webpack defines Vue's bundler feature flags and extracts CSS while retaining the existing stylesheet import order.

Notebook imports pinned Marked and DOMPurify npm dependencies; `package.json` and `package-lock.json` replace the formerly checked-in vendor distributions. Production output includes upstream licenses under `licenses/`. Marked parses GFM and HTML client-side. `markdown-renderer.ts` sanitizes the result with an explicit HTML tag/attribute allowlist before converting the sanitized fragment into Vue nodes. It does not copy arbitrary Vue props, classes, styles, or handlers. Task inputs are forced to disabled checkboxes, and preview headings receive application-owned IDs. Markdown source storage is unchanged.

`app-config.ts` is the canonical app identity. Startup uses it for the document title, Home heading, and navigation drawer identity. One compact application header combines the menu button with the current feature title; feature views do not duplicate that heading. Plain components render the header, navigation, and semantic `main` into an initially empty mount point, so raw template syntax never flashes. CSS imports flow through `index.css` into tokens, base rules, and shell spacing.

## Ownership and dependencies

GitHub Pages uses the same webpack production build (`npm run pages:prepare` is an alias). `webpack.config.mts` creates HTML entry points for Home and each canonical feature path. `build/site-config.mts` validates base paths and routes, and `build/page-metadata.mts` renders canonical, social, and structured metadata. Artwork is copied from `src/assets` to `dist/assets` with stable names; bundle filenames use content hashes. Feature definitions and social metadata refer to public `assets/` paths, keeping these shared data modules browser-neutral.

`.github/workflows/deploy-pages.yml` runs `npm ci`, obtains the Pages base path and URL, builds, and uploads `dist/` only on `workflow_dispatch`. Source and the lockfile are committed; output is not. The HTML base element and webpack public path use the same configured root. `navigation.ts` reads `document.baseURI` to translate local routes into public URLs, independently of the bundle's location. See [github-pages.md](github-pages.md) for setup and manual checks.

| Layer | Responsibility | Allowed local dependencies |
| --- | --- | --- |
| `src/app` | Composition, root Vue state, browser workflow coordination | App modules, features, components, core |
| `src/features` | Feature-specific components, data definitions, business behavior | Features, components, core |
| `src/components` | Reusable, feature-neutral Vue components | Core and other generic components only |
| `src/core` | Feature-neutral utilities | Other core modules only |

Lower layers must never import from `app`; core must never import from features or components. Keep shared data canonical rather than duplicating it across features. Vue owns reactive state and UI rendering. Isolate imperative browser operations in focused modules when they become necessary. Future schemas remain declarative data without DOM operations or Vue behavior.

`src/features/feature-definitions.ts` defines canonical feature IDs, labels, and paths as browser-neutral data. The build configuration imports this data without importing Vue components. `src/features/feature-registry.ts` associates these definitions with plain Vue components for the browser. Each feature lives in its own directory and receives its title from the registry. Add future definitions and register their components, then restart the development server and rebuild production output to generate the new paths. `components/icon.ts` provides generic inline SVG icons without an external icon dependency. `core/ids.ts` provides shared ID generation and validation for directory entries and cards. `core/tree.ts` provides feature-neutral recursive hierarchy lookup, counting, deletion, movement, and group-option construction; feature models bind those operations to their own item unions and keep feature-specific validation, limits, creation, and payload behavior.

Shared interaction infrastructure stays outside individual features. `components/delete-confirmation.ts` renders the canonical destructive confirmation dialog while callers provide feature-specific labels and consequences. `components/use-dialog.ts` owns native dialog open/close lifecycle and KeepAlive cleanup. `components/use-persisted-panel-resize.ts` owns the repeated persisted left-panel resizing behavior used by Notebook, Index Cards, and Word Search. Shared destructive-dialog presentation lives in `styles/delete-confirmation.css`.

`app.ts` derives the selected feature from the URL and owns sidebar visibility. `/` displays Home, `/notebook/` displays Notebook, `/index-cards/` displays Index Cards, and `/word-search/` displays Word Search. `navigation.ts` isolates browser history operations: ordinary link clicks use `pushState`, and `popstate` synchronizes Vue state for Back/Forward. Links retain real destinations and native modified-click/new-tab behavior. No router dependency is needed.

`navigation-drawer.ts` owns the full-height modal drawer, isolating the native dialog operation from feature code. The sidebar starts closed. Vue transitions animate the panel and backdrop; reduced-motion preferences disable animation. The native dialog confines keyboard focus while open, and the page cannot scroll behind it. Navigation closes the drawer and focuses main content after the exit transition. Escape, the close button, or clicking the backdrop dismisses navigation and returns focus to the menu button. Vue's `KeepAlive` preserves mounted UI state when switching during the session, including visits to Home. Reloading keeps the URL-selected page and saved workspace data but resets temporary UI state.

## Workspace and feature data

`app/workspace.ts` owns the canonical reactive workspace, local browser storage, and JSON backup operations. The app passes each feature only its own `model` object. Index Cards mutates that object through feature-owned operations; a deep watcher saves changes. `app/workspace-tools.ts` handles backup controls and stages validated uploads for explicit replacement. `app.ts` composes these controls into the navigation drawer's footer slot, rather than each page. Closing the drawer discards an unconfirmed upload review without applying it. Storage failures remain visible outside the drawer. A successful replacement resets the feature component cache so old selection and editing state cannot survive into the imported data.

Index Cards uses ordered arrays for the root directory and every group's children. Sets have an ordered `cards` collection with separate editable front/back titles and plain-text front/back content. `tree-model.ts` owns creation, lookups, order, cycle/depth guards, and imported data validation. `directory-tree.ts` owns disclosure, inline naming, and drag feedback. The feature entry composes the left directory and selected-item controls, including keyboard/touch alternatives to dragging. Feature CSS lives beside these modules and is imported through the root stylesheet. `card-set.ts` coordinates flipping, navigation, duplication, shuffle, and deletion. `card-paper.ts` renders both editable faces, keeping the hidden face inert and absent from assistive technology. CSS rotates the two faces as one sheet, without mirrored text or timer-driven content swaps; reduced-motion preferences disable the transition. `card-model.ts` owns card creation, validation, limits, and shuffle generation. `review-setup.ts` stages starting-side and order choices in a two-step native dialog; only Start review applies them. `card-set.ts` owns forward/backward/shuffled sequences and resets the visible side on navigation, while editing remains available. A visible session summary explains current progress and settings; Finish review at the last card or End review restores front-first saved-order browsing without changing card data. Temporary review order never mutates saved card order; `card-set.css` owns the ruled-paper appearance and motion. Set location controls are collapsed below the card workspace by default. `card-list.ts` renders the active set’s cards beside the editor, following the current review order and emitting selection/creation requests. `card-list.css` owns the independently scrolling list and stacks it below the editor when the workspace is narrow. Card titles are optional in imported data for compatibility; the editor and list use the canonical title field for the relevant side (`title` for front, `backTitle` for back).

`index-cards.ts` persists only the last selected set ID alongside feature data, restores it on mount, and expands its parent groups. Missing or deleted references are cleared. Card position and review state remain transient; a freshly mounted set starts at the first saved card in normal browsing mode.

Word Search owns a separate ordered library of nested groups and word-search records. `word-search/library-model.ts` owns IDs, hierarchy moves, limits, validation, and committing puzzle setup; `library.ts` owns tree interaction; and `word-search.ts` owns the resizable/collapsible library layout, selection, organization controls, and form/game composition. `puzzle-form.ts` owns the staged creation/editing form and legacy-record summary, with layout in `puzzle-form.css`. The browser-neutral `puzzle-model.ts` defines word normalization, settings, and validation shared by the form and backup loader. New word search does not mutate workspace data until a valid form is submitted; editing also stages changes until Save. Existing version-1 backups without Word Search data are normalized with an empty Word Search library when loaded; older records without puzzle settings remain editable.

`puzzle-generator.ts` places all words using bounded randomized attempts, honoring difficulty directions and compatible overlaps, then fills unused cells. It yields between attempts and supports cancellation; failure leaves any existing grid intact. `game-model.ts` provides canonical directions, straight-line matching, and strict validation of stored rows, solution placements, and found-word locations. `puzzle-game.ts` owns generation, saved progress, completion, hints, temporary answer reveal, persisted quarter-turn board orientation, and restart confirmation. `puzzle-grid.ts` owns mouse dragging, touch endpoint taps, a roving keyboard grid, and coordinate translation between the rotated presentation and canonical saved cells. `puzzle-game.css` keeps large grids horizontally scrollable with readable cells, animates explicit 90° turns, and provides a responsive word bank. Saved games and per-record board orientation use the existing workspace watcher and backup pipeline. Editing words, size, or difficulty clears the old game; title, instruction, study-display, and descriptive-hint edits preserve it. Returning to a record resumes its stored grid and found words. Grid-start hints, per-clue answer reveals, global answer reveal, selections, and pending confirmations are transient. Word Search can optionally replace the visible answer list with saved descriptive hints; players may reveal individual answers without marking them found.

Word Search appearance lives in the optional feature-level `display` object. `display-options.ts` defines choices, defaults, validation, and CSS variables; `display-settings.ts` renders a native dialog with a live grid preview. `word-search.ts` composes Settings into the library footer, persists changes through the existing model, and restores trigger focus on close. `grid-sizing.ts` measures parent layout width and stable workspace/viewport height, with lifecycle cleanup. ResizeObserver ignores content-height changes; viewport events and sizing preferences trigger intentional recalculation. A fixed controls allowance replaces scroll-sensitive grid coordinates, and stable scrollbar gutters keep status updates from changing available width. Fit mode ignores the preferred-size setting, respects a readable 30px minimum cell size, and scrolls instead of shrinking further. Measuring the parent avoids feedback from the snug grid width; the word bank wraps directly beside or below that grid. The frame belongs to the exact-sized grid, not its wider scroll container. `word-outline.ts` renders one SVG capsule per word or hint, including diagonals and overlapping words. Board geometry rotates as one square while letter glyphs counter-rotate to stay upright; found/revealed labels recalculate a readable screen angle so they continue following their displayed word line without becoming upside-down. Saved endpoints remain canonical and unchanged. A transient pointer position drives the active outline; saved endpoints remain discrete canonical grid cells. Highlight movement can be disabled independently, while explicit board turns use their own animation and system reduced-motion preferences always apply.

The backup contains all implemented workspace data for both Index Cards and Word Search. See [workspace-data.md](workspace-data.md) before changing the persisted shape or backup behavior. Schemas stay declarative; validation and mutation functions live outside the data.

The app shell fills the viewport below a compact header, normally 48 pixels tall, with a 44-pixel navigation target. Index Cards fills the remaining main area, with its directory toolbar above an independently scrolling tree. The feature entry owns library collapse state; the mounted directory is hidden when collapsed, retaining expansion and selection state. The collapsed library occupies no space; content uses the full available width. A floating icon at the upper left restores it and keyboard focus follows the toggle. The library slides horizontally while the desktop content expands or contracts; on narrow screens it overlays the content. The collapsed panel is inert and hidden from assistive technology during its exit, then visually hidden. Reduced-motion preferences disable transitions. This UI state is temporary and is not part of backups.

## Growth

Notebook Markdown previews expose heading metadata from the same safe renderer that creates the Vue nodes. `markdown-outline.ts` turns that metadata into nested navigation, and `markdown-editor.ts` scrolls/focuses preview headings without changing the application URL. Contents visibility and download progress are transient editor state. `document-files.ts` handles Markdown filename normalization and UTF-8 upload validation; `library.ts` owns the picker and captures the destination when it opens; `notebook.ts` commits imports through the limit/depth checks in `library-model.ts`. `core/file-download.ts` isolates Blob/object-URL downloads without platform-specific filesystem APIs. The document type catalog marks unimplemented types unavailable for creation while preserving existing records and backups.

Prefer focused modules below 400 lines and split large schemas by section around 500 lines. Responsibility determines boundaries; avoid both monoliths and unnecessary one-function wrappers. Extend persistence and backup support as real feature data is added. Authentication, schema rendering, AI integration, printing, and migrations remain out of scope until requested functionality requires them.

Keep [change-routing.md](change-routing.md) aligned with file ownership. Add specialized documentation only when its functionality exists. Maintenance and manual verification rules live in [AGENTS.md](../AGENTS.md).

## Visual system

`app/home-page.ts` composes the Home launcher from the same feature definitions used by navigation, with native links resolved through `navigation.ts`. Its responsive grid automatically accommodates future apps without placeholder entries. The Home-only footer uses repository/license metadata from `app-config.ts` and the visitor's current local date, refreshed while the page stays open. `styles/home.css` scopes its appearance to Home; feature workspaces are unaffected.

`styles/mobile.css` contains shared overrides for widths up to 700px and touch tablets up to 1100px, leaving desktop rules in their existing owners. Index Cards keeps its overlay breakpoint aligned with `index-cards.ts`; Word Search uses the same media query inside its feature stylesheet. The feature listens for breakpoint changes, uses an inert content area and dismissible scrim while the library overlays it, and closes the library only on explicit item opening. Creating, renaming, and deletion fallback selections keep the library open. Restored sets start with the overlay closed. Small-screen card workspaces scroll vertically as one region, with the card list in a horizontal strip; paper geometry and display settings remain shared with desktop.

Index Cards owns display preferences in the optional `model.display` field. `display-options.ts` is browser-neutral and defines the settings contract and CSS mapping; `tree-model.ts` invokes its validator. `index-cards.ts` applies the settings at the feature root and composes a Settings button into the directory's footer slot. `display-settings.ts` owns the native dialog and live preview, emitting complete replacement options; it does not access storage or app modules. The existing workspace deep watcher saves edits, and backups carry preferences along with card data. Older backups without preferences use defaults without migration.

The Fluent-inspired visual system uses semantic tokens in `styles/tokens.css` and shared typography, button metrics, focus, and reduced-motion rules in `styles/base.css`. Feature styles own layouts rather than redefining control metrics. The library and card list are adjoining workspace panels; only the ruled paper and overlays use elevation. On narrow workspaces the card list becomes a horizontal strip beneath the editor, with selection reveal and arrow navigation on both axes. The fullscreen deletion prompt uses the shared `styles/delete-confirmation.css`. See [design.md](design.md) for styling conventions and manual review guidance.
