# Workspace data

`src/app/workspace.ts` owns one reactive workspace. It saves under `dynamic-learner.workspace.v1` in `localStorage`, scoped to the browser and site origin. Changing host or port uses different browser storage. There is no server-side storage or cross-device synchronization; use a downloaded backup to transfer data. Simultaneous tabs are not synchronized, so edit in one tab at a time.

## Backup format

Downloads are JSON files containing the current canonical workspace:

```json
{
  "format": "dynamic-learner",
  "version": 1,
  "features": {
    "notebook": { "items": [] },
    "todo-list": { "items": [] },
    "index-cards": { "items": [] },
    "word-search": { "items": [] },
    "crossword": { "items": [] },
    "study-guide": { "items": [] },
    "knowledge-check": { "items": [] }
  }
}
```

Each directory entry has an `id`, `kind` (`group` or `set`), and `name`. A group has an ordered `children` array containing groups and sets. A set has an ordered `cards` array. Each card contains `id`, `front`, and `back`, plus optional `title` (front) and `backTitle` fields. Both sides and their titles are plain text; side content can include line breaks. New cards include two empty titles, each limited to 120 characters. Older cards remain valid: their existing `title` stays on the front and a missing `backTitle` displays as blank. Empty text is valid. Existing version-1 backups with empty sets or untitled cards remain valid without conversion. Array position is the manual order, including at the root; there is no alphabetical sorting or duplicate order field. IDs are unique across groups, sets, and cards and do not change on edit or move.

Backups include all currently implemented feature data. Study Guide stores its grouped guide library. List guides store ordered titled sections with plain-text bullets. Map guides store ordered topic stops with snapped x/y positions; each topic owns the same titled-bullet guide structure. The currently selected map topic, active drag, panel width, and library expansion are transient. Notebook stores its grouped document library and each document's persistent type-owned data. Index Cards stores groups, sets, names, nesting, order, and both titles and both sides of every card. Word Search stores its library hierarchy of groups and word-search records. Crossword stores its grouped puzzle library, answer-and-clue setup, generated grid, typed cell progress, and feature-wide display preferences. Todo List stores its flat lists, creation timestamps, task sections, completion states, margin priorities, remembered selection, and library preferences, including lists that have aged into the archive. URLs, open groups, selected groups, current card/side, active review status, review starting side and order, unfinished rename text, and drawer visibility are temporary UI state, not backup content. Resized Library and Cards panel widths are remembered separately in browser-local UI preferences and are also excluded from backups. Icons and app identity remain application code, not user data.

Version-1 backups created before Notebook, Todo List, Word Search, Crossword, or Study Guide persistence may omit those feature records entirely; loading one adds the missing library in memory without requiring a format-version migration.

Notebook document records contain `id`, `kind: "document"`, `name`, a stable `type` ID, and a `data` object owned by that document type. The type catalog is `markdown`, `lined`, and `graph`. **New document** offers Markdown, Lined Paper, and Graph Paper. Markdown data stores `{ "markdown": "..." }`; editing the raw source updates that value directly and the workspace watcher saves it through the normal local-save/backup flow. The Markdown workspace can show source and preview together, source only, or preview only; panel order, split width, contents visibility, and file-transfer status are presentation state and are not stored in the document. Graph Paper stores an independent title, notes, expression records, its coordinate view (center, units per square, and magnification), and optional visual point-and-connection data; the former editing mode field is accepted for compatibility and ignored; legacy empty data normalizes to a blank editable graph. The earlier internal `grid` type is normalized to `graph` when encountered with its pre-editor empty data. Unsupported type IDs, unexpected record keys, and editor data outside the currently defined schema reject an uploaded backup.

Lined Paper stores `{ "text": "...", "title": "...", "marginText": "..." }`, including empty text and line breaks in both writing areas. Each sheet has an independent editable heading, separate from the library filename. `title` belongs to the first sheet; optional `additionalTitles` stores headings for sheets two onward in page order. Older documents retain their heading on the first sheet, and later sheets start blank. Headings stay with page numbers when text reflows; titled sheets remain visible even if body text shrinks to fewer pages. Trailing empty headings are removed when edited. Every additional heading must be a string, and all headings travel in backups. Margin notes appear in a separate right-aligned area to the left of the red line, without placeholder text. It uses plain text without Markdown interpretation. Edits save through the existing workspace watcher and are included in version-1 backups; scroll position and selection are transient. Older lined records with empty `data: {}` normalize to blank text, title, and margin notes on load. Older text-only records retain their text and capture the library filename as an independent title on load. Missing margin notes default to empty; explicitly empty titles stay empty. Non-string text, title, or margin notes, unknown fields, and malformed data reject the backup before replacement. The paper's visual size does not impose a text limit: longer main and margin notes are divided into measured pages. Page boundaries are transient and recomputed for the current font, paper size, ruling, and available width; the full strings remain canonical. Writing in an empty area on a later page inserts blank lines for the preceding pages. The two text streams reflow independently, so margin notes are not anchored to particular main-text passages. The existing browser-storage and backup-file limits still apply.

The Notebook library upload action accepts one UTF-8 `.md` file at a time, up to 8 MB, including empty Markdown files. Imports receive a fresh ID and use the filename without its extension as the document name (up to 120 characters). They are inserted inside the selected group, after the selected document, or at the root if nothing is selected; the target is captured when the picker opens and limits/depth are checked when the read completes. Imports never replace matching names. Download exports the current Markdown source as UTF-8 `.md`, using a filename safe across common desktop platforms; it does not export rendered HTML or library metadata. Workspace backup format is unchanged.

Notebook documents created before document types were introduced used a top-level `markdown` string. Loading one normalizes it in memory to `type: "markdown"` with `data.markdown` while preserving the text. This is a version-1 compatibility normalization rather than a workspace format-version change; the next normal save or downloaded backup uses the canonical typed shape.

The optional `lastSelectedSetId` field records the last opened set through the existing local-save and backup flow. It is a valid ID string or null; older backups may omit it. All library apps now choose the first content entry in display order when opened, including after reload or switching back; remembered IDs remain compatible bookkeeping rather than startup-selection preferences. Grouped libraries skip groups when choosing that entry and expand its ancestors. Selecting or creating a group shows the creation screen without overwriting the remembered content ID; its creation action inserts inside that group. Deleted or unavailable references are cleared, and deleting the selected entry chooses the first remaining entry. Card position, side, and review state are not persisted: a freshly mounted set opens at the first saved card, front side, outside review.

## Todo List library and tasks

The editor toolbar’s Clone list action offers Clone without changes or Clone and skip remaining tasks. Both create and select an independent copy with a fresh creation timestamp, new list/section/task IDs, a bounded “(copy)” name, and the original section order, sorting, priorities, and task states. The library opens for renaming the copy. The skip option marks unfinished, unskipped tasks with text or a priority on the original only, after the copy has been inserted; blank writing rows and completed/already-skipped tasks remain unchanged. Cancel and list-limit failures leave the original unchanged. Archived lists can also be cloned into the active library.

Manual clone review: try both options on a list containing completed, skipped, unfinished, and blank rows in multiple sections. Confirm the copy retains pre-clone states, edits to either list remain independent, and only the skip option changes the original. Cancel the dialog, clone an archived list, rename the copy on a narrow screen, then reload and round-trip a backup.

`features["todo-list"]` contains up to 2,000 flat `items` with `id`, `name`, `createdAt`, optional `sections`, and optional per-list `sectionSort` (`custom`, `name`, or `priority`). Names are nonblank, at most 120 characters. Creation timestamps are canonical ISO UTC strings with representable expiry across supported durations. Creation records the current time automatically; no chosen date or deadline is required. Library IDs must be unique, and unknown fields reject backup replacement. There are no folders or library group records.

Optional `settings` contains required `order` (`newest`/`oldest`) and `dates` (`long`/`short`), plus optional `expiry`: `{ "amount": 1, "unit": "months" }`, where amount is an integer from 1 through 365 and unit is `days`, `weeks`, or `months`. Null expiry disables automatic archiving. Missing expiry defaults to one calendar month; missing settings defaults to newest-first/full dates/one month. Optional `lastSelectedListId` is null or a surviving list ID; deletion clears stale references. Older backups without Todo List load an empty library, and older records without sections get a blank section when opened.

Calendar-month expiry preserves UTC time of day and clamps the day at month-end (January 31 becomes February 28 or 29). Days/weeks advance UTC dates. Age progress is clamped from zero to one and drives gradual gray styling; Never disables fading. Archive membership is derived from creation time, the current browser clock, and current settings. Changes to expiry immediately apply to existing lists and may return archived lists to the active library. A minute timer, visibility refresh, and activation refresh update open sessions. Date labels use the visitor's local timezone. Archived lists remain saved, backed up, and editable. Editing or renaming never renews creation time; there is no automatic deletion.

Each optional section is `{ "id": "...", "title": "POLS 1100", "priority": "P#1", "tasks": [...] }`. Up to 100 sections and 2,000 tasks per list are supported; titles may be blank and are limited to 120 characters. Priority is section-wide freeform margin text up to 12 characters, vertically centered alongside its task rows, excluding the trailing blank writing row. Wrapped task rows contribute their full height. The marker has a fixed P# label and editable suffix, so typing 1 stores/displays P#1; clearing the number removes the saved priority. Missing priority defaults to blank; when opening legacy records with task-level priorities, the first nonblank task priority is copied to the section. Legacy task priority fields remain accepted/preserved for backup compatibility but are no longer edited per task.

Each new task is `{ "id": "...", "text": "My task here", "done": false }`. Task text is a single string, up to 10,000 characters, and may wrap or contain newlines. The section title supplies a shared display prefix on every row (`− POLS 1100: My task here`), without rewriting task text. Clicking any prefix edits that section name for all its tasks; the first unnamed row has a subdued Section affordance. Checking marks a task complete without striking it out. Optional boolean `skipped` (absent means false) represents skipping/deferring: the task stays unchecked, turns black, and receives text strike-through plus a continuous black stroke across each writing line. Done and skipped cannot both be true. The small × button immediately left of each checkbox toggles Skip / defer and clears completion when enabled; checking a skipped task clears its skipped flag. Clicking × again restores the task and removes skipping. The toggle keeps keyboard focus when the row moves. Skipped tasks always render first within their section, with stable order among skipped and regular tasks; this presentation sort preserves saved order for restoring tasks. Move controls stay within each status group, while deletion, undo, and section splitting follow visible rows. No dates or transfers to another list are implied. Checkboxes retain native input behavior with a straight 10px square and a larger checkmark inside an 18px hit area. Priority labels remain transparent and borderless; just the editable number has a subtle outline and a sample-number placeholder. Unnamed section labels and named prefixes use the same typography. Section/task IDs must be unique within a list. Invalid types, unknown fields, duplicate IDs, and exceeded limits reject backups.

The paper is one continuous ruled surface with 36px rows by default; the list name is rendered as the paper's own title rather than as a separate workspace heading. Configurable line spacing drives the ruling, text line height, separators, and textarea height rounding together. A blank writing row separates sections; there are no section heading panels or Add Task buttons. Each list remembers section sorting: Custom uses the canonical array order and exposes section move-up/down controls, while Name and Priority sort only the presentation and preserve that custom order underneath. Every section has an available trailing blank row (persisted empty task or transient draft). A draft becomes a saved task when typing starts. Enter in text inserts a task below (splitting at the selection); Enter on a blank task splits the section at that row, moves following tasks into a new unnamed section, and focuses its name. Enter in the name begins writing; Shift+Enter adds a newline within a task. A quiet row options menu offers ordering, removal, and section naming/deletion; skipping/restoring uses the visible × button beside the checkbox. Skipped tasks have a separate summary count and are not counted as completed. Empty writing rows do not inflate the completion count.

Optional feature-level `display` is a complete Todo List appearance object validated by `display-options.ts`: `font` (serif/sans/mono), `textSize` (80–130%, step 5), `baseline` (-8–8px, step 1), `inset` (4–32px, step 2), `rowSpacing` (28–48px, step 2), `margin` (90–180px, step 2), `prioritySize` (80–140%, step 10), `ink` (pencil/dark/blue), and `paper` (white/cream). Defaults are Times New Roman serif with lining/tabular numerals, 100% text (18px) and priority, calibrated baseline with zero user offset, 12px inset, 36px spacing, 116px margin, pencil ink, and white paper. Priority size scales from the task text size. Preview, section names, task text, and priority inputs share the numeral styling. These preferences apply across lists, persist through the workspace watcher, and travel with backups; absent display uses defaults. Text size and baseline never alter the ruling; line-spacing changes intentionally update both ruling and row heights.

Single-task removal has one-step undo until the editor closes or another task is removed; section and populated-list deletion require confirmation. Removing the last section creates a blank section so writing can continue. Empty lists delete immediately. Archive view, collapse state, rename drafts, empty writing drafts, undo, and confirmations are transient; panel width remains a separate browser-local preference.

Manual review: name a section POLS 1100, write several tasks, assign one P# priority, and check that every row gets the prefix but priority is centered over its task rows and entering 1 gives P#1. Add wrapped tasks and verify the marker recenters, excluding the blank trailing row. Enter on a blank row to start CS 3100; verify exactly one blank line separates sections. Rename a prefix, wrap a long task, use Enter/Shift+Enter, reorder, check/uncheck, and remove/undo tasks. Confirm/cancel section and list deletion. Reload and round-trip a backup, including older task-level priorities. Change expiry among days/weeks/months/Never and inspect fading/archive membership. Use Settings → Display to change fonts, size, baseline, inset, margin, line spacing, priority size, paper, and ink; verify the preview and live editor stay aligned and preferences survive reload/backup. Check that paper lines remain visible behind priorities, the smaller square checkboxes toggle by click and Space, and checked tasks remain unstruck while skipped single-line/wrapped tasks have continuous black strokes in both the editor and Display preview. Use × (including Enter/Space from keyboard focus) to skip a middle task and confirm it moves above regular tasks in its section; restore or check it, reorder within each status group, split sections, and remove/undo while skips are present. Reload and round-trip a backup to confirm skipped flags and ordering. Compare the unnamed section label, named prefix, and Display preview typography; inspect the editable priority number hint and compare letter/digit heights in text such as POLS 1100 and P#1. Review narrow-screen layout, keyboard focus, and resizing manually.

## Mutation and validation

Notebook may contain a feature-level `display` object with separate `lined`, `markdown`, and optional `graph` settings. Missing display data uses canonical defaults. If present, `lined` and `markdown` must be complete and valid; optional `graph` preferences must also be complete when supplied; unknown keys, unsupported choices, and out-of-range values reject the backup. Lined settings include font (`serif`, `sans`, `mono`), text size (80–130%, step 5), ink (`pencil`, `dark`, `blue`), paper (`cream`, `white`, default `white`), ruling (`college`, `wide`), size (`letter`, `a4`), holes (`show`, `hide`), and baseline (-4–4 integer pixels, default 0). Markdown settings include preview font (`sans`, `serif`), preview text size (12–24px), source text size (12–22px), and preview line height (130–220%, step 10). Settings apply to all documents of their type, save immediately, and travel in backups. Reset affects only the selected type's appearance. Graph Paper settings are paper (`white`/`cream`), size (`letter`/`a4`), grid (`quarter`/`fifth`/`metric`), emphasis (`plain`/`fifths`), axes (`show`/`hide`), and numbers (`show`/`hide`). Missing graph preferences use defaults; its tab has live controls and a plotted-sheet preview.

Index Cards may also contain a `display` object, with separate `flashCards` and `fillInTheBlanks` appearance settings shared by sets of that mode. Each contains `paper` (`white` or `cream`), `font` (`serif` or `sans`), `textSize` (80–130 in steps of 5), `cardSize` (75–125 in steps of 5), `ink` (`pencil`, `dark`, or `black`), `baseline` (integer -4–6 pixels), and `blankLength` (`tiny`, `short`, `medium`, or `long`). Blank length is exposed only in the Fill in the Blanks Settings tab: Tiny uses two character widths; Short, the default, uses four character widths. Both use tighter horizontal margins, number spacing, and authoring padding; Medium uses the exact rendered answer width in the selected font; Long preserves the original authoring widths and response-dependent review expansion. The setting applies to authored blanks, review inputs, and the live preview. In review, the selected length is a minimum: blanks expand to fit the rendered response as the learner types, with room for the caret, and shrink back toward the minimum when text is deleted. Missing `blankLength` in older appearance settings defaults to Short. Legacy flat appearance objects normalize to both modes, missing paper defaults to White, and an omitted Fill in the Blanks appearance object inherits Flash Cards settings. Other missing fields, unknown keys, wrong types, and out-of-range values reject the backup before replacement. Defaults are defined in `display-options.ts`; settings save locally and travel in version-1 backups without changing card content.

New groups and sets are created relative to the current selection: a selected group receives the new item at the start of its children, a selected set receives the new item immediately after it among its siblings, and no selection inserts at the start of the root array. Moves preserve a group's entire subtree, reject self/descendant destinations, and maintain the destination's manual order. Names are limited to 120 characters; a blank rename preserves the previous name. The workspace supports up to 5,000 entries and 32 levels of nesting.

Word Search groups and word-search records use their own IDs and ordered hierarchy. Groups may contain groups or word searches, up to 32 levels deep and 5,000 total library items, including at most 1,000 word searches. Creating a group mutates the library immediately. **New word search** stages a form and appends a record to the chosen destination only on valid submission: the selected group, the selected word search's parent, or the root. Limits and destination existence are checked again when saving. Editing preserves the record ID and location; Cancel discards the draft. Form drafts are not saved in backups.

Word-search records optionally contain `puzzle`, with `words`, `size`, `difficulty`, and `instructions`, plus optional `studyMode` and `hints`. `words` contains 3–40 distinct uppercase A–Z strings, each 2–24 letters and no longer than `size`. The square grid `size` is 10, 15, 20, or 24. Difficulty is `easy` (across/down), `medium` (adds forward diagonals), or `hard` (all eight directions). `instructions` is plain text up to 500 characters, including an empty string. `studyMode` is `words` or `hints`; missing values from older backups resolve to `words`. `hints` maps configured words to plain-text descriptions up to 240 characters. Hint mode requires a nonblank hint for every configured word, while word-list mode may retain optional hints for later reuse. Older version-1 records without `puzzle` or without the newer study fields remain valid. Unknown keys, partial settings, invalid word lists, and unsupported values reject the entire backup before replacement.

An optional `game` stores exactly `rows`, `placements`, and `found`, and requires valid `puzzle` settings. `rows` contains `size` strings, each exactly `size` uppercase English letters. `placements` contains exactly one `{ word, start, end }` for every configured word; endpoints are zero-based row-major cell indices. Every location must spell its word along a straight line in a direction allowed by the difficulty. `found` contains unique `{ word, start, end }` records for discovered words. Found locations may read either way and may identify incidental occurrences in the filler, but must spell a configured word in the actual grid. Imports validate these relationships without regeneration. Missing game data is supported; opening a configured puzzle generates its first grid. Invalid grids, directions, duplicate locations for a word, mismatched letters, or unknown fields reject the backup.

Found words save immediately through the workspace watcher. Start over clears progress on the same grid after confirmation. New layout replaces the grid and clears progress only after generation succeeds; failure preserves the existing game. A word-search record may also store optional `boardRotation` as exactly 0, 90, 180, or 270 degrees. Rotating the board updates this value immediately, so orientation survives reloads, backups, restores, puzzle edits, restarts, and new layouts without rewriting the canonical grid rows or solution coordinates. Older records without `boardRotation` open at 0°. Changed words, size, or difficulty invalidate the old game on Save; title, instructions, study display, descriptive-hint edits, and board rotation preserve it. Grid-start hints, per-clue answer reveals, global answer visibility, current selection, focus, and pending restart confirmation are transient and are not saved.

The form accepts words separated by newlines, commas, or semicolons, strips spaces/apostrophes/hyphens, uppercases letters, and combines duplicate normalized words. It previews the exact saved list and reports invalid characters or words too long for the grid. Normalization belongs to form input; imports must already contain canonical words.

Word Search may also contain a feature-level `display` object, separate from library records. It has `font` (`mono`, `sans`, `serif`), optional `weight` (`regular`, `medium`, `semibold`, `bold`), `textSize` (85–125 in steps of 5), `cellSize` (30–48 pixels in steps of 2), `fit` (`screen`, `preferred`), `highlight` (`blue`, `green`, `purple`), and `motion` (`smooth`, `none`). Defaults come from `word-search/display-options.ts`, including 95% text size, regular weight, and instant movement. Older display objects without `weight` use regular weight. Legacy 28px cell preferences remain valid on import and resolve to 30px in the UI; the next settings edit saves the normalized value. Existing explicit text-size and motion choices remain unchanged until edited or reset. Fit mode ignores the saved preferred cell size. Missing display settings in older backups use defaults; partial, unknown, or out-of-range settings reject an upload. Appearance edits save immediately across puzzles and travel in backups without changing grid letters or found words. Measured pixel dimensions, preview state, and pointer positions are not stored.

Manual display checks: change every setting, close with Done and Escape, and confirm trigger focus returns. Reload and restore a backup to check settings persist alongside unchanged puzzle progress; restore an older backup without display settings to check defaults. Upload an invalid display value and confirm no replacement occurs. Reset defaults and verify words, grid, and progress stay intact.

Manual Word Search checks: create a puzzle in a nested group, edit its words/settings, cancel another edit, reload and reopen it, then download and restore a backup. Confirm title, words, grid size, difficulty, instructions, and location survive. Restore an older record without `puzzle` and complete its setup. Try an invalid size, unknown field, duplicate word, or oversized word in an uploaded backup; replacement must be rejected without modifying current data.

Find several words, rotate the board through all four orientations, reload and reopen the puzzle, and round-trip a backup: the orientation, grid letters, and found locations must remain identical. Confirm mouse dragging, touch endpoint selection, keyboard arrows, found outlines, diagonal labels, hints, and failed-selection feedback still line up after each turn. Restore a settings-only record and confirm it generates on opening at 0°. Try malformed rows, out-of-range endpoints, invalid solution directions, an invalid board rotation, and a found word whose letters do not match the grid; uploads must fail without replacement. Edit only instructions and confirm progress and orientation stay; change words and confirm a fresh game without resetting orientation. Cancel both restart actions, then confirm each and inspect the appropriate progress reset.

Crossword groups and crossword records use a separate ordered hierarchy with the same 5,000-item, 32-level, and 1,000-puzzle limits as Word Search. **New crossword** stages a form and saves only after the title, answers, clues, and answer compatibility validate. New records are inserted in the selected group, beside the selected puzzle, or at the root using the same destination rules as Word Search. Editing preserves the record ID and location; changing only the title, clues, or instructions preserves the generated grid and typed progress, while changing the answer set clears the old game so a compatible layout can be generated.

A crossword puzzle contains entries and instructions. Entries contains 2–30 unique answer/clue records. Canonical answers are uppercase A–Z strings from 2–21 letters. Clues are nonblank plain text up to 300 characters; instructions are optional plain text up to 500 characters. The creation form accepts answers separated by newlines, commas, or semicolons, removes spaces/apostrophes/hyphens/ampersands, uppercases letters, combines duplicate normalized answers, and creates a required clue field for each resulting answer. The form checks connectivity live: every answer must belong to one shared-letter connection graph so the generator can build one connected crossword. Imported backups must already contain canonical answers. Early Crossword records may still contain the original optional 11/13/15/17/21 `size` field; it remains accepted for version-1 compatibility but is ignored when generating new layouts.

A crossword game stores exactly rows, placements, and cells. Rows contains the generated solution using uppercase letters and # blocked cells. Placements contains one answer/row/column/direction/number record per configured answer; direction is Across or Down, and clue numbers are assigned in row-major order by unique starting cell, with Across and Down entries sharing a number when they begin in the same square. Cells is a row-major array with one saved string per grid cell: open cells contain either an empty string or one typed A–Z letter, while blocked cells must remain empty. Imports verify dimensions, answer locations, clue numbering, solution letters, blocked/open coverage, and progress before replacement.

Crossword generation is asynchronous and bounded. It chooses a working area automatically from the number and length of answers, places a long answer near the center, and repeatedly adds only entries that intersect the connected grid. After placement it compacts the result to the smallest practical square, so there is no user-selected puzzle size. It enforces word boundaries and avoids side-by-side letter runs that would create unintended entries. If the answers share letters in theory but cannot be arranged cleanly after bounded attempts, the error identifies some of the least-connected answers as likely correction points. Opening a configured crossword without a game generates its first layout. **New layout** replaces the grid and clears progress only after generation succeeds; failure leaves the existing game intact.

Typing directly in crossword cells updates saved progress immediately through the workspace watcher, so progress survives reloads and backup round trips. Across/Down selection, current focus, incorrect-cell highlighting, the random Hint target, global Show answers, and pending confirmations are transient. Reveal cell and Reveal word intentionally write the revealed solution letters into saved progress. Check puzzle compares entered letters without changing them. Start over clears all saved cell progress after confirmation. Completion is derived when every open cell matches the solution; individual clues are marked solved whenever all cells in that placement match.

Crossword may contain an optional complete feature-level display object with font (mono/sans/serif), weight (regular/medium/semibold/bold), textSize (85–125% in steps of 5), cellSize (30–52px in steps of 2), fit (screen/preferred), highlight (blue/green/purple), and blocks (black/soft). Missing display data uses defaults. Fit mode sizes cells from the available workspace while preserving a 30px readable minimum and allowing larger puzzles to scroll. Settings save immediately, apply across all crosswords, and travel in backups without changing puzzle content or progress.

Manual Crossword checks: enter one answer and confirm the form says another is required; enter two answers with no shared letters and confirm it explains why they cannot connect; then add or replace answers until the live status reports one connected crossword. Create a nested puzzle, verify the generated grid is compact and clue numbering/Across/Down placement are correct, type letters with mouse and keyboard, switch direction at intersections, use Backspace/arrows, and reload to confirm progress persists. Check correct/incorrect partial work, use Hint, reveal a cell and a word, temporarily show/hide all answers, then confirm Start over and New layout behavior. Edit only clues/instructions and verify the layout survives; change an answer and verify a fresh automatically sized layout is generated. Exercise every display control, resize/collapse the library, and review narrow/touch layouts. Download and restore the workspace, including an early record with the legacy `size` field, then try malformed dimensions, placement coordinates, clue numbers, blocked-cell progress, invalid answers/clues, and display values; replacement must be rejected without modifying current data.

Empty Notebook groups and documents delete immediately; Markdown documents containing only whitespace count as empty. A Lined Paper document is empty only when its main text, all page headings, and margin notes all contain only whitespace. A Graph Paper document is empty when its title and notes are blank and every expression source is blank and there are no visual points; view/color/visibility edits alone do not count as content. Populated Notebook groups and documents open a fullscreen confirmation; Cancel or Escape leaves them untouched, while Delete removes the entry and its descendants and updates any remembered selection before the workspace saves. Empty Index Card sets/groups delete immediately. Populated Index Card sets/groups open a fullscreen confirmation; Cancel or Escape leaves the directory untouched, while Delete removes the set or the group's entire subtree and saves locally. Selection and expansion state for removed entries are cleared. There is no undo or recycle bin; a previously downloaded backup can restore the workspace through the existing upload flow.

Uploads are limited to 32 MB so downloaded backups can preserve card text even when browser storage fills up. Parsing checks the format/version, allowed fields, unique IDs, names, tree shape, and limits before touching live data. A workspace supports up to 1,000 cards total and 2,000 characters per side. Card data must have valid IDs, string front/back values, and string title/backTitle values if present; unknown fields are rejected. Unsupported versions or feature data are rejected; there is no migration system.

The upload review shows the filename, Notebook library/document counts, Index Cards directory/card counts, Word Search library/search counts, and Crossword library/crossword counts. **Replace workspace** applies the entire validated backup, replacing rather than merging the current data. Cancel leaves the current workspace intact. Download the current workspace before replacement if it needs to be retained. Replacement clears cached feature UI and saves the new data locally.

When browser storage is unavailable or full, changes remain in memory and the UI asks the user to download a backup. An unreadable stored workspace is left untouched and automatic writes remain blocked until the user uploads and confirms a valid replacement. Errors do not silently discard the current in-memory workspace.

## Graph Paper data

Graph Paper requires `{ title, notes, expressions, view }` and optionally stores `visual` and `annotations`. The former `mode` field (`expressions` or `visual`) remains accepted in saved documents but is ignored by the editor and omitted from new sheets. `title` is a string up to 120 characters; `notes` is a string up to 20,000 characters. `expressions` contains at most 20 records, each exactly `{ id, source, color, hidden }`: IDs are valid and unique within the list, source is a string up to 240 characters, hidden is boolean, and color is `blue`, `red`, `green`, `purple`, `orange`, or `teal`. Formula syntax may be incomplete or invalid so drafts can be saved; the editor parses it safely and excludes invalid traces. `view` requires `{ centerX, centerY, unitsPerSquare }` and accepts optional `zoom`, an integer percentage from 25 to 400. Missing zoom uses 100%. Centers are finite between -1,000,000 and 1,000,000, and units per square range from 0.0001 to 10,000. Magnification scales the visible graph independently of units and point coordinates. Reset view centers the origin and restores 100% while preserving units. Unknown keys, missing required fields, and invalid types reject the backup.

Optional `visual` is exactly `{ points, connections }`. There are at most 200 points, each requiring `{ id, x, y, label, color }` and accepting optional boolean `showCoordinates`, with finite x/y coordinates within ±1,000,000, a string label up to 60 characters, and one of the same ink colors. Omitted `showCoordinates` inherits the sheet annotation choice; true always shows the position and false always hides it. There are at most 500 connections, each exactly `{ id, from, to, color }`, referencing two different existing point IDs. All point/connection IDs are valid and unique within the drawing, and duplicate undirected endpoint pairs reject a backup. Deleting a point removes its connections. Dragging or coordinate edits move the point while preserving endpoint references, so connections follow. Both expression and visual content are included in populated-document deletion checks.

Optional `annotations` must be exactly `{ names, coordinates, lengths, areas }`, with all four fields boolean. Missing annotations use `{ names: true, coordinates: false, lengths: false, areas: false }`; new sheets store those defaults. These choices control grid labels and region tinting without changing the drawing geometry. Segment measurements and enclosed-region outlines/areas/perimeters are derived from visual coordinates and connections, cached in the editor, and recomputed after restoring a backup. They are not additional saved fields. Distances use graph units and areas use square graph units; magnification, panning, and changing units per square do not change saved point coordinates or measurements.

Missing visual data in earlier plotted documents defaults to an empty drawing without discarding formulas. Saved sheets with either former mode value show expressions and drawings together. Pre-editor empty `graph` data and the empty `grid` alias normalize to blank content and a centered one-unit-per-square view. Visual drawing including point position-label overrides, sheet annotations, title, notes, expression states, and center/units/magnification persist through the normal workspace watcher. Tool selection, snapping enablement/spacing, grid subdivision count, scrubby preferences, connection anchors, selection, pointer readout, parser feedback, options-panel visibility, touch/trackpad gesture state, and up to 50 drawing undo/redo states are transient. Pinch and two-finger panning update only the saved view; adding a second finger cancels pending drawing without recording an undo edit. Expression plots and visual drawings render together and share the same view; their editors and drawing tools are available simultaneously. Graph Paper uses feature-wide display preferences independently of Markdown/Lined Paper. Per-sheet downloads are removed; the existing whole-workspace JSON backup remains available. See [graph-paper.md](graph-paper.md) for behavior and manual review.

## Card editing and review

Card text updates the canonical workspace on input and uses the existing local-save watcher. New and duplicated cards are inserted after the current card in the saved array. Duplication copies both titles and both sides and creates a new ID. Forward, backward, and shuffled review never change saved order. Starting a review selects the first card of the chosen sequence and every navigation opens the chosen starting side. Canceling setup does not change the active review. Card deletion is immediate, removes both sides, and selects the next available card or the empty-set view. Current position, visible side, and review settings reset when a different set is selected or the workspace is restored.

The right-hand list displays every card in the selected set in the current review order. Titles and previews of the selected starting side update directly from canonical card data; blank titles use a display-only numbered fallback. List selection reveals the configured starting side, updates the active highlight, and does not change the saved order.

Review activity and its progress display are temporary UI state. Finish review and End review restore front-first, saved-order browsing while keeping the current card selected. Editing remains enabled throughout, and ending a review never rolls back edits or changes the saved card order.

Manually edit different front/back titles, flip repeatedly, duplicate, reload, and download/restore a backup. Check an older backup with only `title`: its front title should remain and its back title should be blank. Test back-first review: the list uses back titles, falling back to card numbers for blank titles without exposing front titles. Invalid or oversized back titles must reject uploads without replacing the workspace.

## Review library

Review was formerly named Knowledge Check. The `/knowledge-check/` route, internal module paths, feature ID, and backup/storage key remain unchanged so existing links and workspaces continue to work.

`features["knowledge-check"]` contains `{ items }`, an ordered hierarchy of groups (`{ id, kind: "group", name, children }`) and knowledge sets (`{ id, kind: "set", name, questions, mode?, options? }`). `mode`, when present, is `study`, `quiz`, or `test`; this legacy field is still accepted in backups but no longer restores a selection or records new choices. Opening a knowledge set displays Choose a mode. Leaving for another set/group, a creation screen, or another app clears the chosen mode; returning requires a fresh choice. Cancelling an active-session exit warning keeps the mode and session unchanged. Tips examples can explicitly select their demonstration mode. Names contain 1–120 characters, IDs are valid/unique within the library, and up to 5,000 entries at 32 levels are supported. Missing feature data in old version-1 backups creates an empty library. Earlier `kind: "check"` placeholders with recognized modes/question types become empty sets, preserving names and IDs.

Each set stores up to 200 questions as `{ id, type, prompt, answer, explanation, choices }`. Types are `multiple-choice`, `true-false`, and `short-answer`. Question IDs are valid and unique within their set; text fields and choice strings are limited to 2,000 characters. Multiple-choice questions permit up to eight choices and store the correct choice as answer text. True/false answers are `True` or `False`; an empty answer is accepted for imported drafts. Non-choice questions store an empty choices array. Import validation preserves older incomplete drafts; sessions include ready questions only. Unknown keys, invalid types, malformed arrays, duplicate IDs, and excessive limits reject imports before replacement.

Builders stage changes until Create knowledge set or Save questions; Cancel leaves saved data untouched. New questions default to multiple choice. Once a question has content, saving, adding another question, switching questions, or opening Set options requires a prompt and correct answer, plus at least two distinct nonblank choices for multiple choice. Inline messages explain missing data. Unused blank choices and untouched blank questions are omitted on save. Existing incomplete imported questions must be completed or removed before saving edits. Creation inserts at the start of a selected group, after a selected set, or at the start of the root. Sets/groups can be renamed, dragged, or organized with keyboard controls. Empty sets/groups delete immediately; populated entries require confirmation.

Optional `options` contains `description` (up to 2,000 characters), `timeLimitMinutes` (null for unlimited or an integer from 1–1,440), and `showTestAnswers` (boolean). Missing options default to an empty description, no limit, and visible Test answers. The builder's Set options page edits these values; they save with the set and travel in backups. Time limits and result visibility apply only to Test.

Study opens an overview with Start studying and is answer-first practice without scoring: check responses, retry freely, optionally use the explanation as a hint, or reveal the answer. Wrong Study responses do not automatically expose the answer. End studying returns to the overview, clears practice answers/hints/position, and permits a fresh start; no reload persistence or Resume workflow is implied. All three overviews have shared-icon mode graphics and pills for question count, time policy, and feedback/help policy. Quiz starts from an overview, locks each checked response, gives immediate feedback/explanations and a brief reduced-motion-aware success effect, then shows a final score. Test starts from an overview, allows revisiting/changing responses, holds feedback until submission, and displays either detailed review or a score only according to options. Submitting with unanswered questions requires confirmation; unanswered responses count as incorrect. Short answers match case-insensitively with surrounding/repeated whitespace normalized; other formats match exactly after trimming.

A Test's deadline begins only on Start test, uses elapsed wall-clock time (including background-tab time), and automatically submits current responses at expiry. Session answers, timer deadlines, hints, scores, navigation, and confirmations are transient. Leaving an active Quiz/Test through a library action, builder/mode switch, app navigation, browser Back/Forward, or workspace replacement requires an end-session warning. Cancellation keeps the session; acceptance discards it. Reload/close uses the browser's native warning. Finished sessions can return to an overview and start again while the set stays open. Mode choices are temporary UI state and reset on leaving the set or app, including returning through KeepAlive. Switching sets/modes ends the previous session rather than retaining hidden sessions; saved edits reset session state. Panel width remains a separate browser-local preference.
